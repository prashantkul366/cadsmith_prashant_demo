# Text to CAD — 利用ガイド

部品を日本語または英語の文章で説明すると、5 つの AI エージェントが設計を
計画し、CAD コードを書き、実際の CAD カーネルで構築し、できあがったものを
実測します。得られるのは 3D モデル、編集可能なソース、製図、製造コストの
目安、そしてお使いの CAD で開けるファイルです。

このガイドに出てくる画面上の名称は、すべて実際の表示と同じ言葉で書いて
あります。画面を見ながらそのまま読み進められます。

---

## 1. はじめる前に

アプリケーションはご自分の端末で動かします。Web サイトではありません。

```powershell
.\app\run_app.ps1
```

ブラウザで **http://127.0.0.1:8000** を開いてください。外部には一切公開
されず、待ち受けはご自分の端末の中だけです。

画面上部の帯が状態を示します。**すべて正常** であれば問題ありません。
**一部機能が利用不可** は、一部だけが使えず残りは動く状態です。
**利用できません** はモデルの接続先が未設定という意味なので、
**モデルと実行の設定** を開いて選んでください。

デモの前にまとめて確認したい場合は、事前チェックを実行します。

```powershell
.venv\Scripts\python -m app.tools.doctor --provider bedrock
```

CAD カーネル、レンダラー、認証情報、モデルを順に試し、問題があればその
箇所を名指しで知らせます。

---

## 2. 画面の構成

画面は 3 列に分かれています。

**左 — 対話。** **設計入力** の下に入力欄がひとつあります。その下に
**設計プラン** が表示され、続いて **推論** にエージェントの思考が流れます。
**モデルと実行の設定** でモデルと推論の深さを指定します。

**中央 — 部品。** 3D モデルはドラッグで回転できます。4 つのボタンで表示を
切り替えます。**3D モデル**、**コード**、**パラメーター**、**図面**。

**右 — 結果。** 不要なときは畳める 4 つのパネルです。**プロパティ**、
**カーネルによる実測**、**検証**、**トークン使用量**。

最上部には **履歴**、**元に戻す**、**やり直す**、**全画面**、そして表示言語の
切り替え **EN** / **日本語** があります。

---

## 3. 最初の部品をつくる

1. **部品を説明する** の欄に説明を入力します。例：

   > 100mm × 60mm、厚さ 8mm の平板。6mm の穴を 4 つ、各隅から 10mm 内側に。

2. **CAD を生成** を押します。

3. 左側で工程が進みます。**部品を計画中** → **CadQuery を記述中** →
   **ソリッドを構築中** → **形状を検証中** → **完了**。

4. 中央に部品が現れます。ドラッグで回してください。

軸受やボルト、ワッシャーなどの標準部品は、内蔵のカタログから約 2 秒で
返ります。AI の呼び出しは一切ありません。それ以外はエージェントが動くため
1〜2 分かかります。

入力が面倒なときは **ベンチマーク例** から選んでクリックするだけでも
構いません。

---

## 4. 結果の読み方

**設計プラン** は、こちらの依頼をシステムがどう理解したかです。**目標寸法**
と **制約** が並びます。**まずここを読んでください。** プランが違っていれば
部品も違ってきます。待たずに気づけるだけ時間の節約になります。

**カーネルによる実測** は、できあがったソリッドを CAD カーネルが実際に
測った値です。**外形寸法**、**穴の数**、**穴径**、**閉じたソリッド**。推定値
ではなく実測値です。**（参考）** と付いている項目は参考情報で、それを理由に
部品が却下されることはありません。

**検証** はこの二つを突き合わせます。**判定モデルが合格としました** なら
通過です。**実測により却下** は、カーネルがプランとの実際の差を見つけた
という意味で、その中身も示されます。例：*穴の数 の実測値は 1（期待値 4）*。

これがこのシステムの要点です。**寸法は実測が決めるものであり、意見が決める
ものではありません。** 見た目は正しくても 3mm 違えば製造できません。それを
捕まえるための仕組みです。

**トークン使用量** には、その実行にかかったトークン数がエージェント別に
出ます。

---

## 5. 寸法を変える

中央の表示を **パラメーター** に切り替えます。

生成された部品を形づくっている寸法が、すべてコントロールとして並びます。
ドラッグして指を離すと、カーネルが約 1 秒で部品を作り直します。このとき
**AI の呼び出しも費用も発生しません**。**元に戻す** で値が戻ります。

これができるのは、生成されたものが固定のメッシュではなく、パラメトリックな
スクリプトだからです。数値はすべて、あとから変えられる数値のまま残ります。

バージョン間の移動は、最上部の **元に戻す** と **やり直す** を使います。

---

## 6. 図面

中央の表示を **図面** に切り替えます。

A3 の **製図** が得られます。第三角法ではなく第一角法による 4 面の投影図、
中心線、寸法、表題欄が入ります。絵を描いているのではなく、ソリッドそのもの
を投影しています。

**DXF をダウンロード** で図面を DXF として取り出せます。どの CAD でも開け、
寸法を測り直せます。**PNG で保存** は資料やスライド用の画像です。
**3D に戻る** でモデル表示に戻ります。

図面に公差と材質は入りません。システムのどこでもそれを指定していないため
で、公差を決めていない図面に一般公差の注記を入れれば、それは事実ではなく
主張になってしまいます。

---

## 7. 製造コスト

**製造コスト** のパネルが、その部品をつくる費用の目安を示します。

| | |
|---|---|
| **材料費** | 削り出すビレット・丸棒・板材の、重量による価格 |
| **加工費** | 形状から必要と分かる工程の、分単位の価格 |
| **段取り費** | 使用する機械ごとに発生し、ロット数で割ったもの |
| **1個あたり** | 合計 |

工程は形状から読み取ります。プランが何と呼んでいようと、穴は穴です。
一方 **材料** と **工法** はプランから取ります。この二つだけは形状からは
分からないからです。同じ板でも、レーザー切断の板金か、ビレットからの
フライス加工かは、モデルの中のどこにも書かれていません。

**指示文の中で材質を指定してください。** 見積もりの意味が大きく変わります。
同じ部品をアルミとステンレスで出して比べると、何を計算しているかがはっきり
分かります。

**これは設計案どうしを比べるための目安であって、見積書ではありません。**
単価は編集可能なファイルに入っています。実際に使う前に、自社の実勢価格と
照合してください。

鋳造、成形、積層造形、押出しは意図的に計算しません。これらの費用は主に
型や機械の時間であって主軸の時間ではなく、違う答えを精密に出すことは、
答えを出さないことより悪いからです。

---

## 8. 部品を取り出す

**書き出し** から 5 種類のファイルが得られます。

| | |
|---|---|
| **STEP** | ソリッド（CAD 用） |
| **STL** | メッシュ（造形用） |
| **DXF** | 図面（再計測可） |
| **PNG** | 図面（画像） |
| **.py** | CadQuery スクリプト |

スクリプトは持ち帰る価値があります。これは部品そのものをソースとして表した
もので、このアプリがなくても編集・バージョン管理・再実行ができます。

---

## 9. 実行履歴

**履歴** に、これまでの実行が結果とともに並びます。**収束**、**未収束**、
**失敗**、そして生成されたバージョン数です。

**再生** は、記録済みの実行を実際の形状と実際の判定のまま再現します。
ネットワークもモデルも不要なので、**通信が不安定なときに結果を確実に見せる
手段**になります。

---

## 10. 設定

左の **モデルと実行の設定** を開きます。

**プロバイダー** で接続先を選びます。Amazon Bedrock 上の Claude、Anthropic
API、OpenAI、Ollama、LM Studio、その他 OpenAI 互換のエンドポイント。ローカル
モデルを選ぶとパネルに **ローカル実行です。この端末の外にデータは出ません。**
と表示されます。機密を扱う場合はこの設定を使ってください。

**モデル ID** は役割ごとに指定します。生成用と検証用です。検証側には意図的に
より強いモデルを割り当て、自分の答案を自分で採点しない構成にしています。

> **モデル ID が拒否された場合**、原因は認証情報ではなく ID であることが
> ほとんどです。クラウド側が一覧に出すモデルと、エンドポイントが実際に応答
> するモデルは必ずしも一致しません。事前チェックが表示する一覧から別の ID を
> 試してください。

**改良の反復回数** は、諦めるまでに何回まで自己修正してよいかです。

**推論の深さ** は **低（最速）** から **最大** まで。既定は **高（既定）** で、
たいていの部品はこれで十分です。

---

## 11. 標準部品

軸受、ボルト、ナット、ワッシャー、ねじ、ピン、O リング、ばね、プーリー、
歯車、軸、キー、ブッシュ、リング、カラー、カップリング、止めねじ、
全ねじ棒は、公表されている規格どおりに直接つくられます。約 2 秒、AI の
呼び出しなし、費用なし。規格値のある部品に、でたらめな寸法が入る余地が
ありません。

呼び名でそのまま頼んでください。*6203 の玉軸受*、*M12 の六角ナット*、
*歯数 20、穴径 5mm の GT2 タイミングプーリー*。

曖昧な依頼は、推測せずにエージェントへ回します。

---

## 12. うまく伝わる書き方

- **こだわる数値は必ず書く。** 「中くらいの板」より「100mm × 60mm、厚さ
  8mm」。こちらが指定した寸法は固定されます。
- **数だけでなく位置も書く。** 「6mm の穴を 4 つ、各隅から 10mm 内側に」。
- **コストを見たいなら材質を書く。**
- **設計室の言葉を使う。** ピッチ円、座ぐり、通し穴、二面幅。
- **一度に 1 部品。** アセンブリーには対応していません。

良い例：

> 120mm × 80mm、厚さ 10mm の 6061 アルミ製ブラケット板。M8 のばか穴を
> 4 つ、各隅から 15mm 内側に。中央に 40mm の穴。

---

## 13. うまくいかないとき

| 表示 | 意味 |
|---|---|
| 帯が **利用できません** | モデルの接続先が未設定。**モデルと実行の設定** を開く。 |
| モデル ID が拒否される | 認証情報ではなく ID の問題。事前チェックの一覧から別の ID を試す。 |
| **実測により却下** | 意図どおりの動作。プランと合わなかっただけ。内容を読んで指示文を直し、もう一度。 |
| **未収束** | 反復回数を使い切った。**改良の反復回数** を増やすか、依頼を簡単にする。 |
| **図面を作成できませんでした。** | このソリッドで投影に失敗。3D モデルと書き出しには影響しない。 |
| 最初の部品がとても遅い | 初回起動の分。カーネルの読み込みは最初だけで、2 個目以降は速くなる。 |
| 途中で認証が切れる | 一時的なクラウドの認証期限切れ。サインインし直して再実行。 |

---

## 14. できないこと

頼る前に知っておいてください。

- **一度に 1 部品。** アセンブリー、拘束、部品表はありません。
- **図面に公差や幾何公差は入りません。**
- **コストは目安** であり、比較のためのものです。
- **技術者の代わりにはなりません。** 短時間で候補を出すだけです。依頼どおりか
  どうかは実測が答えますが、その依頼が正しい部品かどうかを判断するのは、
  これまでどおり人間の仕事です。

マルチエージェントのパイプラインとそのベンチマークは、カーネギーメロン
大学の Jesse Barkley、Rumi Loghmani、Amir Barati Farimani の研究成果

アプリケーション — インターフェース、標準部品カタログ、実測による検証、
